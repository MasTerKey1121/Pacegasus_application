### ข้อตกลงระหว่างรัน

- ใช้ session ปัจจุบัน ไม่ออกจากระบบถ้าไม่จำเป็น สลับบัญชีเฉพาะกรณีที่ต้องตรวจสองฝั่ง
- ผู้ใช้ส่ง OTP ล่าสุดให้ผู้ทดสอบกรอกได้ ไม่บันทึกรหัสหรือ token ลงเอกสารและภาพหลักฐาน
- หน้า Home รออย่างน้อย 3 วินาทีก่อนจับภาพเพื่อให้โมเดลโหลด หากยังไม่พร้อมให้รอเพิ่ม
- กรณี Park ใช้ GPS จริง รออย่างน้อย 5 วินาทีและให้ GPS พร้อมก่อนจบ ระยะ 0 ขณะอยู่กับที่ไม่ใช่ข้อพิสูจน์ความแม่นยำ GPS
- กรณีลู่เก็บไว้แยกจาก Park ระยะ 0.10 km ในรอบที่ผ่านมาเป็นค่ากรอกทดสอบ
- ตารางใช้ Easy 3 วันและ Long 1 วัน รอบที่ผ่านมาใช้วันที่ 1/3/5 และ 7 ตามลำดับวันในสัปดาห์ที่เลือก
- ก่อนซื้อ อ่านราคา P และยอด C ปัจจุบัน บันทึกไว้ก่อนกด คาดหวังยอดหลังซื้อ C−P และรายการซื้อหนึ่งครั้ง
- ไม่เริ่มรันทดสอบจากการแก้เอกสารฉบับนี้ การรันจริงให้ดำเนินการตามคำสั่งผู้ใช้ในรอบถัดไป

## 3. วิธีอ่านและบันทึกผล

สรุประดับกรณีทั้ง 88 รายการ: Pass 6, Partial 39 และ Not Run 43 การนับนี้ใช้ขอบเขตเต็มแถว จึงต่างจากจำนวน checkpoint ที่ผ่านในรายงานอัตโนมัติ กรณี Partial อาจมีส่วนย่อยที่ Fail หรือ Blocked ค้างอยู่ โดยเฉพาะรางวัลและ Side Quest ลู่ตามหัวข้อ 5 จึงยังไม่รับรองส่งมอบ

| สถานะ | ความหมาย |
|---|---|
| Pass | หลักฐานยืนยันขอบเขตของกรณีนั้นแล้ว ข้อจำกัดหลักฐานยังระบุไว้แยก |
| Partial | มีเงื่อนไขที่ผ่าน แต่ยังมีค่า บทบาท ขั้นตอน หรือการตรวจคงอยู่ที่ไม่ได้ทำ ยังไม่ถือว่าผ่านทั้งกรณี |
| Fail | ผลจริงขัดกับผลที่คาดหวัง ต้องมีข้อบกพร่องและทดสอบซ้ำ |
| Blocked | เริ่มหรือทำต่อไม่ได้จากข้อมูล/สิทธิ์/สภาพแวดล้อมที่ขาด ระบุส่วนที่ถูกขวาง |
| Not Run | ยังไม่มีหลักฐานของกรณีนั้น |
| N/A | ไม่อยู่ในรุ่นส่งมอบที่รับรอง ต้องระบุเหตุผลและผู้ยืนยันก่อนใช้ |

P1 คือเส้นทางหลัก ความถูกต้องของข้อมูล เหรียญ และสิทธิ์ P2 คือเงื่อนไขรองและการแสดงผล กรณีที่มีหลายค่าให้แยกบันทึกเป็นรหัสย่อย เช่น UAT-07-003/exact-balance และ UAT-07-003/insufficient ไม่ยกผลค่าหนึ่งให้ครอบคลุมทุกค่า

ผลล่าสุดเป็นการทบทวนจากรายงานที่เก็บไว้ ไม่ได้รันทดสอบใหม่ระหว่างเขียนเอกสาร คำว่าเปิดหน้าใหม่ไม่เท่ากับปิดแอปแล้วเปิดใหม่ หรือออกและเข้าสู่ระบบใหม่ รายงานอัตโนมัติที่ผ่านตรวจเฉพาะ assertions ที่ระบุในรายงานนั้น

## 6. ลำดับแนะนำสำหรับการทดสอบที่เหลือ

1. รันลู่ซ้ำเพื่อตรวจรางวัล และจัดการข้อมูล Side Quest ที่ขาด
2. เปิดคลับจากบัญชีรองหลังอนุมัติเพื่อปิดการตรวจสองฝั่ง ใช้ OTP เฉพาะตอนจำเป็นและกลับบัญชีหลักเมื่อจบรอบ
3. เก็บความถูกต้องของข้อมูลและกรณีซ้ำ: Wellness รางวัลไม่ซ้ำ ซื้อซ้อน feedback ซ้ำ OTP ผิด/หมดอายุ และโปรแกรมไม่ซ้ำ
4. ทดสอบสิทธิ์เพื่อน/คลับด้วยบัญชีและบทบาทที่เตรียมเพิ่ม รวมปฏิเสธคำขอ ลบเพื่อน และเปลี่ยนสิทธิ์
5. ตรวจเน็ตขัดข้องก่อนและหลังส่งคำขอ การเปิดแอปใหม่ การกู้ session GPS ระหว่างเคลื่อนที่ และรอยต่อวัน/สัปดาห์ไทย
6. เติมข้อมูลเวอร์ชันของแต่ละรอบ แล้วทดสอบ P1/P2 ที่ยังเป็น Partial หรือ Not Run ให้ครบตามรุ่นที่จะตรวจรับ

รายการนี้เป็นแผนงาน ไม่ใช่การอนุมัติรันทุกกรณีหรือเปลี่ยนข้อมูลจริงทันที
