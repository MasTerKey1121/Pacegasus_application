# Pacegasus — UAT Test Cases

วันที่จัดทำ: 15 ตุลาคม 2026  
สถานะเอกสาร: พร้อมใช้เตรียมการทดสอบ ยังไม่ได้ดำเนินการทดสอบตามเอกสารนี้

## 1. ขอบเขตและวิธีใช้

แบ่งตามข้อตกลงเป็น 7 ชุด: (01) สมัครสมาชิกและ Onboarding (02) Daily Wellness โปรแกรมและตารางฝึกซ้อม (03) บันทึกวิ่ง สรุปผล ประวัติ สถิติ และอันดับ (04) โปรไฟล์และบัญชี (05) เพื่อน (06) คลับ (07) ร้านค้าและ Avatar

**การลบบัญชีอยู่นอกขอบเขต ไม่ต้องกดหรือเรียกใช้การลบบัญชีระหว่างทดสอบชุดนี้** การลบเพื่อน ยกเลิกโปรแกรม ถอดสินค้า และยุบคลับยังเป็นส่วนของฟีเจอร์ที่ทดสอบ โดยใช้ข้อมูลทดสอบที่เตรียมไว้เท่านั้น

- แต่ละแถวคือ Test Case; ทำขั้นตอนตามลำดับ แล้วเทียบกับผลที่คาดหวังทุกข้อ
- P1 = เส้นทางหลัก ความถูกต้องของข้อมูล เหรียญ และสิทธิ์; P2 = เงื่อนไขรองและการแสดงผล
- ทุกกรณีเริ่มเป็น `Not Run`; ใช้ `Pass`, `Fail`, `Blocked` หรือ `N/A` หลังดำเนินการจริง
- ถ้าแถวกำหนดหลายค่าหรือหลายบทบาท ให้บันทึกผลแยกต่อค่า/บทบาท เช่น `UAT-01-010/weight-19` ห้ามผ่านทั้งแถวโดยตรวจเพียงค่าเดียว
- ค่า `C` คือยอดเหรียญก่อนทำรายการ, `W` คือรางวัล Wellness ที่ตกลงไว้, `P` คือราคาสินค้าทดสอบ, `R` คือรางวัลภารกิจที่ตกลงไว้ ต้องกรอกตัวเลขจริงในข้อมูลเตรียมทดสอบก่อนเริ่ม ห้ามใช้ผลตอบกลับจากรายการนั้นเป็นหลักฐานเดียวในการกำหนดยอดที่คาดหวัง
- ตรวจการคงอยู่ของข้อมูลด้วยการออกจากหน้าและเปิดใหม่ หรือออกจากระบบแล้วเข้าใหม่ตามที่ระบุ
- กรณีเน็ตขัดข้อง ให้แยกทดสอบก่อนส่งคำขอ และหลังส่งคำขอแต่ก่อนแอปได้รับคำตอบ; ตรวจสถานะล่าสุดก่อนลองใหม่เพื่อพิสูจน์ว่าไม่เกิดข้อมูลซ้ำ
- เวลาข้ามวันและข้ามสัปดาห์อ้างอิง `Asia/Bangkok`; เตรียมเวลาหรือข้อมูลจำลองในระบบทดสอบโดยผู้ดูแล ไม่เปลี่ยนเวลาระบบจริงของผู้ใช้งาน
- เอกสารนี้เป็นเกณฑ์ตรวจรับที่เสนอจากโค้ดและเส้นทางใช้งาน ไม่ใช่การรับรองว่าทุกกรณีทำงานแล้ว หากกติกาในหัวข้อ 4 ยังไม่ตกลง ให้ใช้ `Blocked` สำหรับกรณีที่พึ่งพากติกานั้น

## 2. ข้อมูลและสภาพแวดล้อมที่ต้องเตรียม

| รหัส | ข้อมูลทดสอบ |
|---|---|
| A-NEW | อีเมลใหม่ที่รับ OTP ได้ และ Google สำหรับผู้ใช้ใหม่ โดยไม่ใช้บัญชีเดียวกันสำหรับกรณีที่ต้องเริ่มใหม่ |
| A-PENDING | บัญชีที่ทำ Onboarding ค้าง พร้อมระบุขั้นตอนล่าสุดที่บันทึกสำเร็จ |
| A-RUN | บัญชีที่ทำ Onboarding ครบ มีโปรแกรมและแผนวิ่งวันนี้ |
| A-EMPTY | บัญชีที่ทำ Onboarding ครบ แต่ยังไม่มีประวัติวิ่งและไม่มีโปรแกรม |
| A, B, C | บัญชีแยกกัน 3 บัญชี พร้อม UID; ตอนเริ่มกรณีเพื่อนต้องไม่เป็นเพื่อนและไม่มีคำขอค้าง เว้นแต่ระบุไว้ |
| CLUB | บัญชีหัวหน้า รองหัวหน้า สมาชิก และคนนอกคลับ พร้อมคลับทดสอบจำนวน 19 และ 20 คน รวมถึงคลับที่อนุญาตให้ยุบได้ |
| SHOP | สินค้ายังไม่เป็นเจ้าของ ราคา P, สินค้าที่มีแล้ว, สินค้าปรับสีได้/ไม่ได้ และรายการหมดช่วงขาย |
| MONEY | บัญชียอดเหรียญ 0, P−1, P และมากกว่า P; บัญชี EXP ใกล้เลเวลเพิ่ม พร้อมสูตร EXP ที่รับรอง |
| HISTORY | รายการวิ่งสำเร็จ 2 km/600 วินาที และ 3 km/1,200 วินาที ในช่วงเดียวกัน; มี session ยกเลิกและยังไม่จบแยกไว้ |
| RANK | ข้อมูลบุคคล/คลับที่มีระยะทางเท่ากัน มีผู้มีระยะทางมากกว่า 0 อย่างน้อย 51 ราย และข้อมูลก่อน/หลังขอบเขตสัปดาห์ |
| DEVICE | รุ่นเครื่อง OS เวอร์ชันแอป และที่อยู่ระบบทดสอบ; GPS และสลับแอปใช้เครื่องจริงของแพลตฟอร์มที่จะส่งมอบ |

ผู้ดูแลเตรียมข้อมูลและบันทึกยอดตั้งต้นก่อนทดสอบ; แต่ละกรณีที่เปลี่ยนความสัมพันธ์ สมาชิกคลับ เหรียญ หรือโปรแกรม ต้องคืนเงื่อนไขตั้งต้นหรือใช้บัญชีชุดใหม่ก่อนทำกรณีถัดไป

## 3. Test Cases

### UAT-01 สมัครสมาชิกและ Onboarding

เส้นทางต่อเนื่อง: สมัคร → ยอมรับนโยบาย → OTP/Google → Onboarding 4 ขั้นตอน → หน้าหลัก

| ID | ระดับ | สิ่งที่ตรวจ | เงื่อนไข/ข้อมูล | ขั้นตอน | ผลที่คาดหวัง |
|---|---|---|---|---|---|
| UAT-01-001 | P1 | สมัครด้วยอีเมลสำเร็จ | A-NEW; รับอีเมลได้ | 1. เปิดสมัคร 2. กรอกข้อมูลที่หน้าจอบังคับ 3. ยอมรับนโยบาย 4. ขอ OTP 5. กรอกรหัสล่าสุดภายในอายุ | ยืนยันสำเร็จ ไปเริ่ม Onboarding และอีเมลผูกกับบัญชีที่สมัคร |
| UAT-01-002 | P1 | ยังไม่ยอมรับนโยบาย | A-NEW | 1. กรอกข้อมูลครบ 2. ไม่ยอมรับนโยบาย 3. พยายามสมัคร | ดำเนินการสมัครไม่ได้ มีคำแนะนำ และไม่มีสถานะยอมรับนโยบายถูกบันทึกแทนผู้ใช้ |
| UAT-01-003 | P2 | อีเมลไม่ถูกต้อง | อีเมลว่าง และ `runner@` | 1. กรอกแต่ละค่า 2. ขอ OTP | แจ้งให้แก้ไขอีเมล ไม่ไปขั้นตอนยืนยันว่าได้ส่งรหัสสำเร็จ |
| UAT-01-004 | P1 | OTP ผิดและไม่ครบ | มีคำขอ OTP ปัจจุบัน | 1. ใส่รหัสไม่ครบ 6 หลัก 2. ใส่รหัสผิด 6 หลัก 3. ใส่รหัสถูกก่อนครบจำนวนครั้งที่อนุญาต | รหัสไม่ครบ/ผิดไม่ผ่าน รหัสที่ถูกต้องผ่านได้ถ้าคำขอยังใช้ได้ ข้อความไม่ทำให้เข้าใจว่าเข้าสำเร็จ |
| UAT-01-005 | P1 | OTP หมดอายุ | ทราบอายุ OTP ของระบบทดสอบ | 1. ขอรหัส 2. รอให้หมดอายุ 3. ยืนยันรหัสเดิม | ไม่เข้าสู่ระบบ แจ้งว่ารหัสใช้ไม่ได้ และมีทางขอรหัสใหม่ |
| UAT-01-006 | P2 | ส่ง OTP ใหม่และจำกัดการส่ง | มีคำขอ OTP | 1. กดส่งใหม่ก่อนครบช่วงรอ 2. รอครบ 3. ส่งใหม่ 4. ใช้รหัสและ reference ของรอบล่าสุด | ช่วงรอป้องกันการส่งถี่ หลังครบส่งใหม่ได้ และยืนยันรอบล่าสุดสำเร็จ |
| UAT-01-007 | P1 | ป้องกันใช้ OTP ซ้ำ | มีรหัสที่ยืนยันสำเร็จแล้ว | 1. ออกจากระบบ 2. พยายามใช้รหัสและคำขอเดิมอีกครั้ง | รหัสที่ใช้ไปแล้วไม่สร้าง session ใหม่ ต้องยืนยันตัวตนด้วยคำขอใหม่ |
| UAT-01-008 | P1 | สมัคร/เข้าสู่ระบบด้วย Google | Google ใหม่และ Google ที่เคยใช้แล้ว; แยกผลแต่ละกรณี | 1. เลือก Google 2. ยืนยันบัญชี 3. ทำตามหน้านโยบายถ้ามี | ผู้ใช้ใหม่ผ่านขั้นตอนนโยบายตามที่รับรองแล้วไป Onboarding; ผู้ใช้เดิมได้บัญชีเดิมและไปหน้าตามสถานะ ไม่มีบัญชีซ้ำ |
| UAT-01-009 | P2 | ยกเลิก Google | ยังไม่เข้าใช้แอป | 1. เปิด Google 2. ยกเลิกเลือกบัญชี | กลับหน้าลงชื่อเข้าใช้ ไม่มี session และไม่ถือว่ายอมรับนโยบายแล้ว |
| UAT-01-010 | P1 | ข้อมูลพื้นฐานและค่าขอบเขต | ผู้ใช้ที่อยู่ขั้น 1; ใช้ค่าตามหัวข้อ 4 | 1. เว้นช่องบังคับ 2. ใส่วันไม่มีจริง/วันเกิดอนาคต 3. ใส่ค่าต่ำกว่าขอบเขต/เท่าขอบเขต/เกินขอบเขตของอายุ น้ำหนัก ส่วนสูง วันวิ่ง 4. บันทึกค่าถูกต้อง | ข้อมูลผิดไม่ผ่าน ช่องผิดมีคำแนะนำ ค่าที่รับรองว่าถูกต้องผ่าน และหน่วยชัดเจน |
| UAT-01-011 | P1 | ประวัติบาดเจ็บและโรคประจำตัว | อยู่ขั้น 2; แยกบัญชีหรือย้อนแก้ | 1. เลือกไม่มีแล้วไปต่อ 2. ทดสอบเลือกมีและกรอกรายละเอียด 3. ย้อนกลับตรวจ | ไปต่อได้ตามข้อมูลบังคับ เก็บคำตอบตรงกับที่เลือก และเมื่อเปลี่ยนเป็นไม่มีไม่เหลือข้อมูลขัดแย้ง |
| UAT-01-012 | P1 | เป้าหมายและประวัติวิ่ง | อยู่ขั้น 3–4 | 1. ไม่เลือกเป้าหมายแล้วไปต่อ 2. เลือกเพิ่มความอึดโดยไม่ตั้งระยะทาง 3. เลือกประวัติไม่เคยวิ่งและระยะตามตัวเลือกที่บังคับ 4. จบ Onboarding | ต้องมีเป้าหมายอย่างน้อยหนึ่งข้อ เป้าหมายเพิ่มความอึดไม่สร้างเป้าระยะทางเอง เมื่อกรอกครบเข้าสู่หน้าหลักได้ |
| UAT-01-013 | P1 | บันทึกและกลับมาทำ Onboarding ต่อ | A-PENDING | 1. บันทึกขั้นหนึ่งสำเร็จ 2. ปิดแอป 3. เปิดและเข้าใช้บัญชีเดิม 4. ทำต่อจนจบ | ขั้นที่บันทึกแล้วไม่สูญหาย กลับเข้าสู่ขั้นตอนที่เหมาะสม เมื่อจบแล้วเข้าใหม่ไม่ถูกเริ่ม Onboarding ใหม่ |
| UAT-01-014 | P1 | บันทึก Onboarding ตอนเน็ตขัดข้อง | อยู่ขั้นที่ยังไม่บันทึก | 1. กรอกข้อมูล 2. ตัดเน็ตและบันทึก 3. ต่อเน็ต 4. ตรวจสถานะและลองใหม่ | ไม่ข้ามขั้นโดยอ้างว่าสำเร็จทั้งที่ยังไม่บันทึก ข้อมูลไม่ซ้ำ และทำต่อได้เมื่อเชื่อมต่อกลับมา |

### UAT-02 Daily Wellness โปรแกรมและตารางฝึกซ้อม

เส้นทางต่อเนื่อง: เข้าใช้ → เช็กอิน → สมัครโปรแกรม → จัดตาราง → บันทึก → ตรวจแผนหน้าหลัก

| ID | ระดับ | สิ่งที่ตรวจ | เงื่อนไข/ข้อมูล | ขั้นตอน | ผลที่คาดหวัง |
|---|---|---|---|---|---|
| UAT-02-001 | P1 | Wellness ครั้งแรกของวัน | วันนี้ยังไม่เช็กอิน; บันทึก C และ W | 1. เปิด Wellness 2. ตอบครบ 5 ด้าน 3. บันทึก 4. กลับหน้าหลัก | บันทึกค่าตรง วันนี้เป็นทำแล้ว ยอดเหรียญเท่ากับ C+W และงานเช็กอินบนหน้าหลักปรับตามสถานะ |
| UAT-02-002 | P1 | Wellness ไม่ครบ | วันนี้ยังไม่เช็กอิน | 1. ตอบบางด้าน 2. บันทึก | แจ้งให้กรอกครบ ไม่ถือว่าเช็กอินแล้ว และไม่ได้รับรางวัล |
| UAT-02-003 | P2 | Wellness ค่าปลายสเกล | ใช้คะแนน 1 และ 5 แยกผล; ทราบสูตรคะแนนที่รับรอง | 1. เลือกคะแนนปลายสเกลทั้ง 5 ด้าน 2. บันทึก 3. เปิดตรวจค่า | รับเฉพาะช่วง 1–5 ค่าที่เก็บตรง และคะแนนรวมตรงสูตรที่ทีมรับรอง |
| UAT-02-004 | P1 | แก้ไข Wellness ไม่รับรางวัลซ้ำ | วันนี้ทำแล้ว; บันทึกยอด C หลังรางวัลแรก | 1. เปิดแก้ไข 2. เปลี่ยนค่า 3. บันทึก 4. เข้าใหม่ | เห็นค่าล่าสุด ยังมีรายการวันนี้รายการเดียว และยอดไม่เพิ่มจากการแก้ไข |
| UAT-02-005 | P1 | กดบันทึก Wellness ซ้ำ/ตอบกลับหาย | วันนี้ยังไม่เช็กอิน | 1. กดบันทึกติดกัน 2. ทดสอบตัดเน็ตหลังส่งในอีกรอบ 3. ต่อเน็ตและตรวจวันนี้ก่อนลองใหม่ | มีเช็กอินหนึ่งรายการและรางวัลหนึ่งครั้ง สถานะสุดท้ายตรงกันระหว่างหน้าเช็กอินกับหน้าหลัก |

## 6. เกณฑ์ส่งตรวจรับที่เสนอ

1. ยืนยันกติกาและข้อมูลตั้งต้นที่ใช้ในหัวข้อ 4 ให้ครบสำหรับฟีเจอร์ในขอบเขต
2. ทุกกรณี P1 และค่าย่อยที่เกี่ยวข้องต้อง Pass; ไม่มีปัญหาข้อมูลหาย เหรียญผิด รับรางวัลซ้ำ หรือเข้าถึงข้อมูลผิดบัญชีค้างอยู่
3. P2 ต้องดำเนินการครบ; ถ้ายังคง Fail ต้องมีผู้รับผิดชอบรับทราบผลกระทบและอนุมัติข้อยกเว้นเป็นรายข้อ
4. Blocked และ Not Run ไม่เท่ากับ Pass; N/A ต้องมีเหตุผลและการรับรองว่าอยู่นอกขอบเขต
5. ชุด 01, 02, 03 และ 07 ต้องมีหลักฐานเส้นทางต่อเนื่องด้วยบัญชีเดียวกันตามจุดเชื่อมที่เกี่ยวข้อง พร้อมตรวจข้อมูลหลังเข้าใหม่
6. ปัญหาที่แก้แล้วต้องทดสอบซ้ำกรณีที่เสียและเส้นทางที่เชื่อมโยง ก่อนผู้รับผิดชอบลงชื่อรับรองผล UAT
